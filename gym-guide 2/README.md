# الدليل الاحترافي للتضخيم — Gym Guide PWA

دليل تدريب تفاعلي (تضخيم عضلي + تصحيح Anterior Pelvic Tilt) مبني كتطبيق ويب تقدمي (PWA) قابل للتثبيت والعمل بدون إنترنت. النسخة v1.0.0 كانت إعادة هيكلة إنتاجية كاملة للنسخة الأصلية ذات الملف الواحد. النسخة v1.1.0 أضافت محرك تمارين كامل، وv1.2.0 وسّعت مكتبة التمارين لـ104 تمرين عبر 12 عضلة. **النسخة الحالية (v1.7.0)** أضافت صفحة My Profile — أول Assessment/Onboarding في التطبيق (هدف، مستوى، معدات، حدود تدريب) — فوق نفس الأساس المعماري وبدون أي تغيير في برنامج التمرين نفسه (انظر CHANGELOG.md لتفاصيل كل نسخة).

## تشغيل المشروع محليًا

المشروع عبارة عن ملفات ثابتة (Static Files) فقط — لا يحتاج أي بناء (build step) أو تثبيت حزم. لأن `index.html` يستخدم ES Modules (`<script type="module">`)، المتصفحات تمنع تحميلها مباشرة من نظام الملفات (`file://`)، فلازم تُقدَّم عبر سيرفر محلي بسيط:

```bash
cd gym-guide
python3 -m http.server 8080
# افتح http://localhost:8080 في المتصفح
```

أو باستخدام Node:

```bash
npx serve .
```

كل موديول له مسؤولية واحدة واضحة، ويصدّر (export) بس الدوال اللي المفروض تُستخدم من برّه. لإضافة تمرين جديد أو يوم جديد، `data.js` هو المكان الوحيد اللي محتاج تعديل — والعرض (rendering) بيتبني تلقائيًا منه.

## أهم قرار معماري: لماذا اتغيّرت طريقة الحفظ؟

النسخة الأصلية كانت بتستخدم `window.storage.get/set` — وده API خاص بمتصفح Artifacts بتاع Claude.ai بس، مش موجود في أي موقع حقيقي منشور. لو اتنشر المشروع زي ما هو، أي زائر حقيقي هيلاقي إن التطبيق مش بيحفظ أي حاجة (بل هيرمي خطأ في الكونسول).

الحل: `js/modules/storage.js` دلوقتي بيستخدم `localStorage` الحقيقي المتاح في كل المتصفحات، مع:
- تغليف البيانات بنسخة إصدار (`{version, data}`) عشان أي تعديل مستقبلي على شكل البيانات يقدر يعمل migration بأمان.
- Debounce تلقائي (250ms) لتقليل عدد الكتابات.
- كشف احتياطي (`isStorageAvailable`) لو المتصفح رافض `localStorage` (مثلاً وضع خاص صارم جدًا)، فيرجع لتخزين مؤقت في الذاكرة بدل ما يكسر التطبيق بالكامل.
- حفظ فوري (`persistImmediately`) عند إخفاء الصفحة (`visibilitychange`/`pagehide`) عشان محدش يفقد آخر تعديل.

كل الموديولات التانية بتتعامل مع `STATE` من `store.js` بنفس الشكل اللي كانت شغالة بيه قبل كده — التغيير محصور في `storage.js` بس.

## محرك التمارين (Workout Engine) — v1.1.0، مكتبة موسّعة في v1.2.0

تاب "مكتبة التمارين" فوق مكتبة التمارين المرجعية في `js/modules/exercises-data.js` (155 تمرين عبر 12 عضلة — منهم 21 تمرين بحزام المقاومة و37 تمرين منزلي (20 بدون أي أدوات + 17 بكرسي/فوطة/شنطة): صدر/ظهر/أكتاف/باي/تراي/ساعد/كوادز/هامسترينج/جلوت/سمانة/بطن-كور/ترابيز):

- **بحث فوري** بالاسم الإنجليزي/العربي أو العضلة الأساسية (`#exerciseSearch`، مع debounce 250ms).
- **فلاتر**: عضلة (شرائح Chips لـ12 مجموعة)، معدات (Select)، مستوى الصعوبة (Select) — كلها تتجمع مع بعض (AND) ومع البحث النصي. لما تفلتر على عضلة معينة، بيظهر صندوق مقدمة قصيرة (`#groupNoteBox`) يشرح الأساس العلمي لترتيب التمارين جوه المجموعة دي.
- **ترتيب داخل كل مجموعة**: الأول التمارين الأكتر توثيقًا علميًا لاستهداف العضلة (EMG، مراجعات منهجية، تجارب حديثة)، وبعدها بقية الخيارات الشائعة اللي ممكن اليوزر يفضّلها لأسباب معدات/راحة/عادة — تفاصيل الترتيب والمصادر في CHANGELOG.md.
- **مفضلة (⭐)**: تتحفظ في `STATE.favorites` عبر نفس آلية `persist()` الموجودة، فتفضل بعد إعادة تحميل الصفحة أو حتى أوفلاين. زرار "المفضلة فقط" بيفلتر عليها.
- **بطاقة تفاصيل لكل تمرين**: العضلة الأساسية/الثانوية، المعدات، المستوى، خطوات الأداء (Instructions)، الأغلاط الشائعة (Common Mistakes)، النصايح (Tips)، رابط فيديو يوتيوب، ورابط MuscleWiki — بنفس شكل بطاقة التمرين (`ex-card`) المستخدمة في باقي التطبيق (صفر تصميم بصري جديد).
- **روابط الفيديو**: التمارين اللي ليها فيديو ID متأكد منه (نفس اللي مستخدم فعليًا في أيام البرنامج) بتفتح الفيديو مباشرة؛ الباقي بيفتح بحث يوتيوب جاهز (`YT_SEARCH`) — بدل ما نخترع ID غلط ممكن يكون مكسور.

**إحماء تكيّفي (Adaptive Warm-up)** — موجود من v1.0.0 وبيتوسع في v1.1.0:
كل يوم تدريب بيولّد تلقائيًا (حسب `warmupType: upper/lower`): إحماء عام (كارديو) ← موبيليتي ديناميكي ← تنشيط عضلي مستهدف (خاص بالتمارين) ← التمارين الأساسية ← **إطالة ثابتة بعد التمرين (جديد)**. تمارين تصحيح القوام (APT) متضافراش مع الإحماء التلقائي عمدًا — فضلت في مكتبتها المنفصلة `aptLibrary` زي ما طلب.

## قرارات معمارية أخرى

- **إلغاء `onclick="..."` المضمّن بالكامل.** كل عنصر تفاعلي دلوقتي بيحمل `data-action="..."`، ومستمع أحداث (event listener) واحد مُفوَّض (delegated) في `app.js` هو المسؤول عن التوجيه لكل الموديولات. الفايدة: مفيش دوال عامة (`window.xxx`) لازم تتعرّض، وإضافة زرار جديد بيبقى مجرد سطر واحد في جدول `ACTIONS`.
- **ES Modules بدل سكريبت واحد ضخم.** كل ملف مسؤول عن حاجة واحدة، وده بيسهّل القراءة والاختبار والصيانة على المدى الطويل.
- **الوصول (Accessibility).** كل الأزرار الشبيهة بـ div (بطاقة تمرين، مجموعة قابلة للطي، صندوق سيت، عنصر تشيك ليست) بقت `role="button"`/`role="checkbox"` مع `tabindex="0"` وتفعيل بلوحة المفاتيح (Enter/Space)، بالإضافة لـ `aria-expanded`/`aria-pressed`/`aria-checked` بتتحدث لحظيًا. كل التابات بقت `role="tab"` جوه `role="tablist"` مع `aria-selected`. مؤشر التركيز (focus outline) بقى ظاهر لأول مرة.
- **التوجيه بالـ hash.** التاب النشط بيتسجل في الـ URL (`#day1` مثلاً)، فزرار الرجوع في المتصفح وإعادة تحميل الصفحة بيرجعوك لنفس التاب بدل ما يرموك للرئيسية دايمًا.
- **دعم عدم الاتصال (Offline).** `service-worker.js` بيخزن هيكل التطبيق كامل (HTML/CSS/JS/الأيقونات) عشان يفتح ويشتغل بالكامل بدون إنترنت بعد أول زيارة. البيانات المحفوظة (STATE) أصلاً في `localStorage` فمتاحة دايمًا بغض النظر عن الشبكة. لينكات الفيديوهات الخارجية (يوتيوب/MuscleWiki) طبيعي متفتحش أوفلاين — وده موضّح لليوزر عبر شريط تنبيه أوفلاين تلقائي.

## الميزات المحفوظة بالكامل (زي ما هي بالظبط)

- محتوى التمارين والتغذية والإصابات وتعليم APT — بدون أي تغيير في النص أو الأرقام.
- تتبع السيتات، تسجيل الوزن/العدات، حساب 1RM (معادلة Epley) وحجم التمرين، حفظ آخر 8 جلسات لكل تمرين.
- وضع الجيم (Gym Mode) الموجّه بتايمر راحة تلقائي واهتزاز عند انتهاء الوقت.
- حاسبات البروتين/السعرات/الماء، تشيك ليست الاستشفاء، مقياس الإرهاق.
- كل الألوان، الخطوط، والتخطيط البصري (RTL بالكامل) بدون أي تعديل.

> **ملاحظة:** التطبيق الأصلي كان بتصميم غامق (dark) واحد فقط بدون خاصية تبديل لوضع فاتح، وبلغة عربية واحدة بدون مبدّل لغة — تم الإبقاء على هذا بالضبط لأن دي كانت الحالة الفعلية للمشروع، ومفيش تعليمات بإضافة ميزات جديدة.

## اختلاف بسيط عن هيكل المجلدات المقترح

اتّبعنا هيكل `js/modules/` المقترح، لكن أسماء بعض الملفات اتغيّرت لتعكس الميزات الحقيقية الموجودة في المشروع بدل أسماء عامة لميزات مش موجودة أصلًا (زي `favorites.js` أو `charts.js` أو `settings.js`، واللي التطبيق الأصلي معندوش مفضلات ولا رسوم بيانية ولا صفحة إعدادات). بدل كده اتضافت `recovery.js`, `nutrition.js`, `injury.js`, `store.js` عشان تغطي الصفحات والمنطق الموجود فعليًا. الهدف: صفر كود ميت أو موديولات فاضية.

## إعادة النشر / تحديث مستقبلي

لو عدّلت أي ملف داخل `css/`, `js/`, `index.html`, `manifest.json`, أو `icons/`، لازم تزوّد رقم النسخة في أول `service-worker.js` (المتغيّر `CACHE_NAME`)، وإلا الزوّار الراجعين هيفضلوا شايفين النسخة القديمة المخزّنة (cached) بدل التحديث.

## المتصفحات المدعومة

أي متصفح حديث بيدعم ES Modules (Chrome/Edge/Firefox/Safari الإصدارات الحديثة). مفيش استخدام لأي أدوات بناء (Webpack/Vite/إلخ) — الملفات بتتحمّل زي ما هي، فأي سيرفر ملفات ثابتة (static hosting) كفاية لنشر المشروع (GitHub Pages، Netlify، Vercel، إلخ).

## البرامج والجدول الأسبوعي (Phase 2)

من صفحة **Program** تقدر تختار:

| الأيام/أسبوع | التقسيم | الجلسات |
|---|---|---|
| 3 | Full Body A/B/C (الأصلي، الافتراضي) | `day1`, `day2`, `day3` |
| 3 | Push / Pull / Legs | `dayPushA`, `dayPullA`, `dayLegsA` |
| 6 | PPL ×2 (A تقيل / B بتركيز مختلف) | `dayPushA` … `dayLegsB` |

وبعدها بتختار أنهي أيام الأسبوع (من السبت للجمعة) أيام تدريب وأنهي راحة. الجلسات بتتوزع بالترتيب على أيام التدريب المختارة. تغيير البرنامج أو الجدول **مابيمسحش** أي سيت أو وزن أو سجل — كل يوم ليه مفاتيح حالة مستقلة (`<dayKey>-main-<i>`).

لإضافة يوم جديد: ضيفه في `data.js` (مفتاح camelCase من غير `-` ويبدأ بـ `day`) وضيفه في `PROGRAMS` جوه `schedule.js`.

## محرك بدائل التمارين (Phase 3)

`js/modules/exercise-alternatives.js` موديول منطق صافي (من غير DOM أو STATE) — الواجهة بتاعته اتضافت في Phase 4 (تحت). ممكن يتستدعى من أي مكان:

```js
import { getAlternatives, getHomeAlternatives, getBestAlternative, availableCategoriesFromProfile } from "./modules/exercise-alternatives.js";

getAlternatives("flat-barbell-bench");                       // { close: [...], partial: [...] }
getAlternatives("flat-barbell-bench", { category: "band" });  // تبويب واحد: machine | barbell | dumbbell | cable | band | bodyweight | home
getAlternatives(id, { availableCategories: availableCategoriesFromProfile(["dumbbells"]) }); // حسب معدات المستخدم
getHomeAlternatives("rdl");                                  // { none: [بدون أي أدوات], adaptable: [محتاج كرسي/فوطة/شنطة + note] }
getBestAlternative(id);                                      // أحسن بديل واحد (close ثم partial)
```

- **close** = نفس نمط الحركة ونفس العضلة المستهدفة تحديدًا (صدر علوي ≠ أوسط ≠ سفلي، سمانة غاسترو ≠ سولس). **partial** = بيشارك العضلة أو الحركة بس، أو عنده حد أقل لزيادة الأحمال (بوزن الجسم، أحزمة للتمارين المركبة) — الواجهة لازم توضح الفرق.
- كل تمرين له: نمط حركة، عضلة مطابقة، غرض (builder/isolation/stability)، فئة معدات، ومستوى صعوبة. كل تمرين من البرنامج له بديل لأي حد معاه نوع معدات واحد بس (أحزمة / وزن جسم / دمبلز / كابلات / أجهزة) وله بديل منزلي.
- التمارين اللي مالهاش بديل close (الديبس، الأبر رايت رو، الزوتمان كيرل، الديد هانج، السايد بلانك) متسجلة في `PARTIAL_ONLY_REASONS` بسبب مكتوب بالعربي والإنجليزي بدل ما نعرض قايمة بدائل أضعف من غير تفسير.
- `ALT_OVERRIDES` لتثبيت زوج معين لما حكم المدرب يتفوق على القواعد (حاليًا ليج بريس ↔ هاك سكوات، وبايسكل كرانش ↔ الكرانش).
- التمارين الجديدة **من غير رابط صورة توضيحية** عن قصد — الروابط بتتضاف بس بعد التحقق من صفحة التمرين المباشرة.

## زرار البدائل واستبدال التمرين (Phase 4)

كل كارت تمرين أساسي (في صفحة اليوم وفي وضع الجيم) وكل كارت في مكتبة التمارين فيه زرار **بدائل · Alternatives**. بيفتح شاشة (bottom sheet) فيها:

- **فلاتر نوع الأداة**: الكل / أجهزة / بار / دمبلز / كابلات / أحبال مقاومة / وزن الجسم / منزلي — كل فلتر عليه عدد النتايج، والفلاتر الفاضية بتختفي.
- **«معداتي بس»**: لو حددت معداتك في الملف الشخصي بيتفعّل تلقائي ويخفي اللي محتاج معدات مش عندك (مع عدّاد بالمخفي). لو مفيش معدات محفوظة بيظهر تلميح بدل الفلتر.
- **بدائل قريبة (Close)** و**بدائل جزئية (Partial)** في قسمين منفصلين، وكل بديل عليه جملة تشرح ليه: نفس العضلة؟ نفس نمط الحركة؟ أسهل/أصعب؟ حمله محدود؟ ولو منزلي: إيه اللي بيحل محل الأداة.
- لو التمرين مالوش بديل مطابق (ديبس، أبر رايت رو…) بتظهر الجملة اللي بتشرح السبب بدل قايمة من غير تفسير.
- التمارين الموجودة فعلًا في نفس اليوم **مش بتظهر** كبدائل.

**الاستبدال الآمن** (`replacements.js`): الاستبدال مش بيعدّل `data.js` أبدًا. بيتسجل في `STATE.exerciseOverrides[dayKey][index] = { id, originalId, since }`، والمكان (slot) بيفضل بنفس مفتاح الحالة `<dayKey>-main-<i>` فكل حاجة تانية (وضع الجيم، التتبع، اقتراح الزيادة، الداشبورد) بتشتغل زي ما هي. وقت الاستبدال:

1. أي سيتات مكتملة أو أوزان مكتوبة على التمرين القديم النهارده بتتسجل في تاريخه كجلسة **جزئية** (`partial: true`).
2. السيتات والأوزان والـ RPE وتاريخ التمرين القديم **بتتنقل (مش بتتمسح)** لمفاتيح أرشيف `<slotKey>~<exerciseId>` ومربوطة بـ id التمرين.
3. التمرين الجديد بيبدأ بسيتات وأوزان فاضية وتاريخه الخاص. نفس السيتات×العدات والراحة بتفضل.
4. «رجّع التمرين الأصلي» بيرجّع كل بياناته زي ما كانت. كل سجل جلسة جديد فيه `exerciseId`.

شاشة تأكيد بتقول بالظبط إيه اللي هيتحفظ قبل أي تغيير.

## التقدم والداشبورد (Phase 5)

- **بطاقة النهاردة** (`dashboard.js` + `progress.js › getTodayState`): تمرين اليوم من جدولك، أو يوم راحة + الجلسة الجاية.
- **منحنيات التقدم** (`progress-ui.js`) في صفحة سجل التقدم: لكل تمرين أفضل 1RM تقديري وتغيّر الحجم، ومتابعة التمرين عبر الاستبدال (`exerciseId`) وعبر الأيام. الجلسات الجزئية بتتحسب في الرقم القياسي والمجموع الأسبوعي بس مش في منحنى الحجم.
- **الأسبوع بيبدأ السبت.** التواريخ كلها بالتوقيت المحلي.
- الوصول: `nav` مع `aria-current`، أسماء صفحات، نقل تركيز بعد التنقل، رسوم لها بدائل نصية وجداول، تباين ≥ 4.5:1 للنصوص.

### فحوصات التطوير (اختيارية)

```bash
node tools/validate-alternatives.mjs   # بيانات البدائل + المكتبة (Phase 1 + 3)
node tools/validate-schedule.mjs       # بيانات الأيام + منطق الجدول (Phase 2)
node tools/validate-replacements.mjs   # الاستبدال الآمن: السيتات/الأوزان/التاريخ (Phase 4)
python3 tools/e2e-phase2.py            # متصفح حقيقي — البرامج والجدول (محتاج: pip install playwright && playwright install chromium)
python3 tools/e2e-phase3.py            # متصفح حقيقي — مكتبة التمارين الموسّعة
python3 tools/e2e-phase4.py            # متصفح حقيقي — شاشة البدائل والاستبدال
```

فحوصات Phase 5: `node tools/validate-progress.mjs` و`python3 tools/e2e-phase5.py`.
